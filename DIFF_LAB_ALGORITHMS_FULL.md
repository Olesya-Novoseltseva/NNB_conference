# Диофантова лаборатория: полный разбор алгоритмов и вычислительных блоков

Этот документ описывает, как **реализованы в коде** и как **работают математически** все основные алгоритмы и блоки расчетов в проекте.

Проект: `diofield-lab`  
Основной UI: `src/App.tsx`  
Математическое ядро: `src/core/*.ts`

---

## 1) Общая логика системы

Приложение объединяет два мира:

1. Режим над целыми числами `Z`:
   - применяются частные решатели (линейные, одномерные),
   - применяется модульное препятствие,
   - выполняется ограниченный перебор в кубе `[-N, N]^k`,
   - отдельно показывается граница по H10 (неразрешимость в общем случае).

2. Режим над конечным полем `F_p`:
   - проверяется, что `p` простое,
   - выполняется полный/усеченный перебор по `F_p^n`,
   - результат интерпретируется как конечный decision-поиск.

Центральный оркестратор: `analyzeDiophantineInput()` в `src/core/diophantineAnalyzer.ts`.

## 2) Формат полиномов и парсер выражений

### 2.1 Как хранится полином в коде

Файл: `src/core/polynomial.ts`

- Полином хранится как массив мономов:
  - `Monomial = { coefficient: number, powers: Record<string, number> }`
  - `Polynomial = { monomials: Monomial[] }`
- Пример:
  - `3*x^2*y - 5` хранится как два монома:
    - `{ coefficient: 3, powers: { x: 2, y: 1 } }`
    - `{ coefficient: -5, powers: {} }`

### 2.2 Нормализация

`normalizePolynomial()`:
- приводит одинаковые мономы к одному ключу (одинаковый набор степеней),
- суммирует коэффициенты,
- удаляет нулевые коэффициенты.

Математически это приведение к канонической записи:
`a*m + b*m = (a+b)*m`.

### 2.3 Парсер

`parsePolynomial()` и `parseEquation()`:
- токенизация (`number`, `variable`, `operator`, скобки),
- рекурсивный спуск по приоритетам:
  - выражение: `+`/`-`,
  - term: `*`,
  - power: `^`,
  - unary: унарные `+`/`-`.
- `parseEquation("L=R")` возвращает `L-R`, то есть стандартную форму `P=0`.

Математически: любое уравнение приводится к виду `P(x1,...,xn)=0`.

### 2.4 Вычисление значения

- `evaluateInteger(poly, assignment)` — подстановка в `Z`.
- `evaluateFiniteField(poly, assignment, p)` — подстановка в `F_p` через `mod`.

Это базовая операция, на которой строятся все переборы и проверки решений.

## 3) Блок элементарной теории чисел

Файл: `src/core/numberTheory.ts`

### 3.1 `gcd` и `gcdMany`

- `gcd(a,b)` — классический алгоритм Евклида.
- `gcdMany([a1,...,an])` — свертка `gcd` по массиву.

Математически: вычисляется НОД, главный критерий разрешимости линейных диофантовых уравнений.

### 3.2 `extendedGcd(a,b)`

Возвращает `gcd, x, y` такие, что:
`a*x + b*y = gcd(a,b)`.

Это коэффициенты Безу, которые затем масштабируются под правую часть `c`.

### 3.3 `solveLinearDiophantine(a,b,c)`

Решает `a*x + b*y = c`:
- если `gcd(a,b)` не делит `c`, решений нет;
- иначе строится частное решение `(x0,y0)` и шаги параметризации:
  - `x = x0 + t*(b/g)`
  - `y = y0 - t*(a/g)`.

## 4) Арифметика конечного поля `F_p`

Файл: `src/core/finiteField.ts`

- `mod(value,p)` — корректная нормализация в диапазон `[0, p-1]`.
- `isPrime(p)` — проверка простоты (trial division).
- `add/sub/neg/mul` — операции по модулю `p`.
- `pow(base, exponent, p)` — бинарное возведение в степень.
- `inv(a,p)` — обратный элемент через `extendedGcd`.

Математическая основа:
- при простом `p` класс вычетов образует поле;
- для `a != 0` существует `a^{-1}` mod `p`.

## 5) Линейные системы и линейные диофантовы блоки

### 5.1 Извлечение линейной формы

Файл: `src/core/diophantineLinearForm.ts`, функция `extractLinearForm(poly)`.

Из `P=0` строится форма:
`a1*x1 + ... + an*xn = rhs`,
если все члены имеют степень не выше 1.

Если встречается степень >1, возвращается `null`.

### 5.2 Решение одного линейного уравнения в `n` переменных

Файл: `src/core/linearDiophantineMany.ts`, функция `solveLinearDiophantineMany(coeffs,c)`.

Логика:
- Проверка делимости `gcd(a1,...,an) | c`.
- Рекурсивная сборка частного решения:
  - сначала решается для префикса коэффициентов,
  - затем расширяется через коэффициенты Безу для пары `(g_prev, a_n)`.

Математика:
- критерий существования: `d = gcd(a1,...,an)` делит `c`;
- при выполнении критерия существует бесконечное семейство решений, в коде выводится одно частное.

### 5.3 Линейная система 2x2

Файл: `src/core/diophantineLinearForm.ts`, функция `trySolveLinearSystem2x2(line1, line2)`.

Сценарии:
- `D != 0`:
  - правило Крамера,
  - отдельная проверка целочисленности `numX % D === 0`, `numY % D === 0`.
- `D == 0`:
  - вырожденная система,
  - проверка совместности,
  - если совместна — показывается одно целочисленное решение.

## 6) Однопеременное уравнение над `Z`

Файл: `src/core/univariateInteger.ts`, функция `solveUnivariateInteger(poly, variable)`.

Шаги:

1. Нормализация полинома.
2. Выделение корня `x=0`:
   - пока свободный член ноль, делим полином на `x`.
3. Разбор по степени остатка:
   - Степень 1: `ax+b=0`, проверка целочисленности `-b/a`.
   - Степень 2: дискриминант `D=b^2-4ac`, проверка полного квадрата и делимости на `2a`.
   - Степень >=3: кандидаты среди делителей свободного члена (идея теоремы о рациональных корнях, но в реализации берутся именно целые кандидаты).

Математический смысл:
- 0-корень выделяется факторизацией `x^k`.
- Для квадратичного случая используется критерий целых корней через целочисленный дискриминант.
- Для высоких степеней применяется конечный набор необходимых кандидатов по свободному члену.

## 7) Перебор и верификация решений

Файл: `src/core/search.ts`

### 7.1 Пространство поиска

- Для `Z` в окне `[-N,N]^k`:
  - мощность `(2N+1)^k` (`countIntegerSearchSpace`).
- Для `F_p^n`:
  - мощность `p^n` (`countFiniteFieldSearchSpace`).

### 7.2 Перебор

- `bruteForceInteger(polynomial, variables, limit, maxChecks)`
- `bruteForceIntegerSystem(system, variables, limit, maxChecks)`
- `bruteForceFiniteField(system, variables, p, maxChecks)`

Общий механизм:
- генератор декартова произведения `cartesianProduct`,
- последовательная проверка подстановок,
- ранняя остановка по `maxChecks`,
- возвращается:
  - `solutions`,
  - `checked`,
  - `total`,
  - `truncated`.

### 7.3 Проверка свидетельства

- `verifyAssignmentInteger()`
- `verifyAssignment()`

Это чистая верификация кандидата: вычислить все левые части и проверить, что они равны нулю.

## 8) Модульное препятствие (очень важный блок)

Файл: `src/core/modularObstruction.ts`, функция `findModularObstruction(...)`.

Идея:
- перебираются простые `p` из заданного списка;
- для каждого `p` решается система в `(Z/pZ)^n` полным перебором (или до лимита);
- если для некоторого `p` перебор **полный** и решений нет, получаем строгое отрицание существования решения в `Z`.

Математика:
- если `x in Z^n` решение, то `x mod p` всегда решение mod `p`;
- контрапозиция:
  - нет решений mod `p` => нет решений в `Z`.

Это не эвристика, а корректный отрицательный сертификат при полном переборе по модулю.

## 9) Оценка сложности и времени

Файл: `src/core/complexityEstimate.ts`

- `estimateSecondsForChecks(totalChecks, checksPerSecond)`:
  - оценка `T = totalChecks / checksPerSecond`.
- `formatHumanDuration()`, `formatBigNumber()`:

## 10) Центральный анализатор лаборатории

Файл: `src/core/diophantineAnalyzer.ts`, функция `analyzeDiophantineInput(text, options)`.

### 10.1 Что делает по шагам

1. Парсит ввод как систему уравнений.
2. Собирает переменные и максимальную степень.
3. Если режим `Fp`:
   - проверяет простоту `p`,
   - запускает `bruteForceFiniteField`,
   - формирует отчеты.
4. Если режим `Z`:
   - пытается линейный 2x2 блок,
   - иначе линейный `n`-переменный блок,
   - иначе одномерный блок,
   - запускает модульное препятствие,
   - дает оценку сложности по окну,
   - выполняет ограниченный перебор в окне,
   - при нелинейности добавляет карточку о границе H10.

### 10.2 Результат

Возвращается `DiophantineAnalysisResult` (`src/core/diophantineTypes.ts`) с набором карточек `AlgorithmReport`, которые визуализируются в `src/components/AlgorithmReportPanel.tsx`.

## 11) MQ-блок и сведение 3-SAT -> MQ

### 11.1 Сведение

Файл: `src/core/satToMq.ts`, функция `convert3SatToMq(clauses)`.

Реализация:
- булевы переменные кодируются элементами `GF(2)` (`0/1`),
- литерал `not x` кодируется как `1 + x`,
- "ложность литерала" задается отдельным полиномом,
- для каждой 3-SAT клаузы:
  - кубический член раскладывается через вспомогательную переменную `y_i`,
  - добавляются две квадратичные связи:
    - `y_i = false1 * false2`
    - `y_i * false3 = 0`

Итог — система степени не выше 2 (MQ-форма).

### 11.2 Проверка и эксперимент

Файл: `src/App.tsx`:
- `MqScreen` вызывает `convert3SatToMq`,
- `verifyAssignment` проверяет свидетельство,
- `runMqBenchmark` запускает серию случайных MQ-задач:
  - генерация `createRandomMqSystem`,
  - поиск существования через `scanExistenceBruteforce`,
  - усреднение `avgChecked`, `avgTimeMs`, доли solved/truncated.

Математический смысл:
- демонстрация разницы между "проверить кандидат" и "найти кандидат";
- рост трудности через размер пространства `p^n`.

## 12) Блок калибровки устройства

Файл: `src/core/deviceBenchmark.ts`

Функция `runIntegerAssignmentBenchmark()`:
- выполняет фиксированный цикл вычислений `evaluateInteger`,
- измеряет `durationMs`,
- оценивает `checksPerSecond`,
- кэширует результат.

Использование:
- в `src/App.tsx` значение подставляется в оценку времени перебора в лаборатории.

Это прикладной инженерный блок, чтобы оценка сложности была ближе к конкретному ПК пользователя.

## 14) Что в проекте является строгим, а что демонстрационным

Строгое (корректные математические утверждения в рамках модели):
- критерий делимости через `gcd` для линейных уравнений,
- Крамер с проверкой целочисленности,
- отрицательный вывод через модульное препятствие при полном переборе mod `p`,
- корректная арифметика в `F_p` (для простых `p`).

Демонстрационное/ограниченное:
- перебор в окне `[-N,N]^k` не решает задачу во всем `Z^k`,
- для степеней >=3 в одномерном случае используется ограниченный метод кандидатов,
- MQ-бенчмарк — учебный, не промышленный солвер.

## 16) Короткий вывод

В лаборатории реализована не попытка "решить H10", а корректная инженерно-математическая система:
- частные решатели там, где это теоретически возможно,
- строгие отрицательные сертификаты через модульные препятствия,
- прозрачный ограниченный перебор,
- отдельная учебная ветка про MQ/NP с работающим кодовым экспериментом.

Именно это делает проект одновременно полезным как учебный инструмент и как аккуратную демонстрацию границ алгоритмов в диофантовой тематике.
